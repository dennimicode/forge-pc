# Действия владельца: пошаговая настройка

Все пункты `USER_ACTION` собраны в `public/site-config.js`. Этот файл публичный. В нём допустимы адрес сайта, числовые ID счётчиков и URL картинок, но **не пароли, SMTP-ключи и приватные токены**. Для счётчиков не нужны серверные API-токены.

Если используете исходники — меняйте `public/site-config.js` и запускайте сборку. Если загрузили готовый `dist/` — меняйте его копию `site-config.js` в корне опубликованного сайта.

## 1. Опубликовать учебный сайт

1. Зарегистрируйтесь / войдите на [GitHub](https://github.com/), создайте публичный репозиторий, например `forge-pc`.
2. Загрузите содержимое папки проекта в корень репозитория, ветка `main`. Папку `node_modules` не загружайте. Файл `package-lock.json` и папка `.github/workflows` нужны.
3. Settings → Pages → Source: **GitHub Actions**.
4. Actions → Deploy Vue site to GitHub Pages → Run workflow. Если workflow не показан, проверьте, что `.github/workflows/pages.yml` находится именно в корне репозитория.
5. После успешного запуска URL появится в Settings → Pages и в результате job `deploy`.
6. Впишите его в `siteUrl`, например `https://yourname.github.io/forge-pc/`.

Альтернатива без установки Node: распаковать `forge-pc-pages.zip`, загрузить файлы в корень отдельного репозитория и выбрать Deploy from a branch → main / root. Перепубликация — обычный commit обновлённых файлов. Не смешивайте этот режим с workflow исходного проекта.

## 2. LiveInternet — ЛР3

1. Откройте [регистрацию сайта](https://www.liveinternet.ru/add). Укажите окончательный URL с путём репозитория, название, описание, email и пароль для статистики.
2. Получите код в [генераторе счётчика](https://www.liveinternet.ru/code). Выберите компактный логотип 88×31, подходящий тёмной теме, и вариант из двух изображений: отдельный хит и логотип в подвале.
3. Скопируйте ссылку на свою статистику из кабинета в `analytics.liveInternet.statUrl`. Установите `analytics.liveInternet.enabled: true`. Для обычной регистрации ID не требуется. В `badgeStyle` уже стоит `11.6`; если выбрали другой вид, скопируйте суффикс из выданного URL `https://counter.yadro.ru/logo?…`.
4. Перепубликуйте. Откройте сайт и разрешите аналитику. В подвале появится настоящий логотип, а хиты уйдут на `counter.yadro.ru`.
5. В кабинете проверьте свои пять адресов страниц. На GitHub Pages регистрируйте папку сайта: `https://username.github.io/repository/` с завершающим `/`. LiveInternet поддерживает регистрацию каталогов; это позволяет выделить проект внутри общего хоста. Для ссылки в подвале используйте именно скопированный `statUrl`. Поддомен/домен регистрируется в сервисе отдельно.

Код использует стандартный раздельный вариант: один пиксель на загрузку каждой HTML-страницы; изображение логотипа отдельно в общем подвале. Пароль статистики в проект не добавляется. Описание вариантов и регистрация: [официальная справка](https://www.liveinternet.ru/help/faq.html).

## 3. Рамблер/Топ-100 — ЛР4

1. Войдите на [Топ-100](https://top100.rambler.ru/), откройте «Мои сайты», затем «Добавить сайт». Введите адрес и название, создайте счётчик.
2. Из выданного кода скопируйте числовое значение `project` в `analytics.rambler.id`.
3. Включите «Участвовать в рейтинге», заполните категорию, описание и регион. Это действие в аккаунте, код сайта не может включить его самостоятельно.
4. В расширенных настройках включите аналитику блоков и учёт разделов / пользователей, если они представлены в текущем интерфейсе. В список data-атрибутов добавьте **`forge-block`** — без `data-`. В коде: `attributes_dataset: ['forge-block']`; на элементах: `data-forge-block="home::hero"` и аналогичные значения.
5. Для обычных страниц уже передаётся `chapters: [page]`. `userId` — случайный постоянный псевдоним браузера после согласия посетителя. Авторизации здесь нет: один человек на двух устройствах не объединяется в одного пользователя.
6. В генераторе выберите цвет/виджет. Скопируйте **URL картинки** из выданного `img src` в `analytics.rambler.badgeUrl`. Нужна HTTPS-ссылка. Не вставляйте в это поле весь HTML. Пока URL пуст, сайт показывает текстовую ссылку на статистику вместо выдуманного изображения.
7. Перепубликуйте, разрешите аналитику, выберите сборку и нажмите «К оформлению заявки». В кабинете заведите событие **`config_selected`**. Создайте учебную заявку в форме и заведите **`order_created`** — событие её создания в браузере. Используется `top100Counter.trackEvent(name, params)`.
8. Отметьте эти события как целевые / конверсии в кабинете, проверьте раздел «Конверсии». Настройка целей в аккаунте обязательна: отправка события сама по себе не создаёт ваш отчёт.
9. Если добавите собственный домен, внесите его в разрешённые/дополнительные домены счётчика. Создайте два отчёта по плану ANALYTICS.md и сохраните их в кабинете.

Источник: [создание счётчика](https://help.rambler.ru/top100/top100-faq/1540), [параметры SDK](https://top-100-writer.gitbook.io/top100-documentation/nastroika-sbora-i-otpravki-dannykh/veb-schyotchik/parametry-schyotchika-top-100), [собственные события](https://top-100-writer.gitbook.io/top100-documentation/nastroika-sbora-i-otpravki-dannykh/veb-schyotchik/metody-po-rabote-s-schyotchikom-top-100/otpravka-sobstvennykh-sobytii).

## 4. Рейтинг Mail.ru — ЛР5

1. Войдите на [Рейтинг Mail.ru](https://top.mail.ru/), добавьте свой сайт и создайте счётчик. Зарегистрируйте полный опубликованный URL.
2. Из кода `_tmr.push({id: ...})` скопируйте числовой ID в `analytics.mail.id`.
3. Выберите логотип/цвет под тёмную тему и скопируйте HTTPS-адрес картинки из выданного HTML в `analytics.mail.badgeUrl`. Не используйте адрес 1×1 счётчика как логотип.
4. В настройках целей создайте **две цели типа «JavaScript-событие»** с точными именами `config_selected` и `order_created`.
5. Перепубликуйте. После разрешения аналитики и нажатия «К оформлению заявки» сработает первая цель. Вторая срабатывает после создания валидной учебной заявки кнопкой «Создать учебную заявку». Скачивание TXT/JSON и перезагрузка не повторяют цель. Доставка владельцу и оплата не выполняются.
6. Проверьте посещения, источники, популярные страницы и цели. Создайте два сложных отчёта, изучите раздел таргетингов по плану ANALYTICS.md. Названия разделов могут меняться; ориентируйтесь на назначение отчёта и актуальный кабинет.

Просмотры отправляются через `pageView`, события через `sendEvent`, цели через `reachGoal`. Источники: [JS API](https://top.mail.ru/help/ru/api/jsapi), [настройка целей](https://top.mail.ru/help/ru/counter/targets).

## 5. Учебная форма — без подключения сервисов

Форма работает сразу после публикации. Выберите комплектацию, введите тестовое имя и email, подтвердите локальное сохранение и нажмите «Создать учебную заявку». Перезагрузите страницу: последняя заявка останется под формой. Доступны TXT, JSON, копирование и удаление. Новая заявка заменяет предыдущую в этом браузере.

Сервер, почтовый аккаунт, SMTP, база и API-токены **не нужны**. Заявка не передаётся владельцу сайта и не появляется у него в репозитории. Если браузер запрещает локальное хранилище, заявка доступна только в открытой странице — скачайте файл до её закрытия. На другом устройстве или в другом браузере заявки нет. TXT/JSON содержат введённые контакты: используйте тестовые данные.

GitHub Pages обслуживает HTML, CSS и JavaScript. Он не запускает Go и не имеет обработчика для серверного приёма формы. Автоматическая доставка и общий список заказов требуют внешнего сервиса; в учебной версии они не используются. Описание платформы: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## 6. Учебные данные компании

Поля `company` можно оставить пустыми. Email и телефон, если заполнены, дают обычные ссылки для связи и не используются для отправки формы. Каталог изменяется в `src/data/catalog.json`, затем пересобирается. Учебные цены и условия не являются реальным предложением о покупке.

## 7. Проверка аналитики после публикации

1. Разрешите аналитику в баннере. При отказе счётчики не загружаются; такой визит не должен увеличивать их показатели.
2. При необходимости включите `analytics.debug: true`. В консоли появятся обезличенные имена событий. Это локальная диагностика, не подтверждение доставки в сервис.
3. В инструментах браузера → Network проверьте `counter.yadro.ru`, `st.top100.ru`, `kraken.rambler.ru`, `top-fwz1.mail.ru`. При блокировщике рекламы сбор может отсутствовать.
4. Перейдите по всем пяти страницам. Это отдельные HTML: дополнительные виртуальные просмотры не нужны.
5. Проверьте события сначала в интерфейсах сервисов, затем в отчётах за подходящий период. Задержки обработки возможны.
6. После проверки выключите `debug`. Собирайте данные 1–2 недели, привлеките не менее 50 реальных пользователей — требование всех трёх работ. Не заменяйте их искусственными перезагрузками или фиктивными отчётами.
